# 全模型 GPU 移植与验证（2026-10-10）

本轮实现了原仓库已有 12 种模型的 GPU 滤波、约束、追踪和记录路径，以及张量模型的分支种子生成和第二轮 GPU 追踪。**实现覆盖不等于全部通过精度验收：完整追踪仍有下表所列差异。** 用户已允许混合精度；尚未确认是否接受长轨迹分歧，因此严格检查保持失败状态，没有放宽阈值。

## 模型与精度状态

| 模型 | GPU 实现 | 官方/合成用例严格对照 CPU |
|---|---|---|
| Simple1T、Simple2T | 专用内核，FP64/混合 FP32 | 通过 |
| Simple3T | 通用内核，FP64/混合 FP32 | 两张量输入上的三张量拟合未通过，最大位置差 23.985 mm |
| Full1T | FP64 | 未通过，最大位置差 0.397514 mm |
| Full2T | FP64 | 位置差约 0.000290 mm；协方差误差 0.164795，标量检查未通过 |
| Full3T | FP64 | 未通过，CPU 63 点、GPU 131 点 |
| Simple1T-FreeWater、Full1T-FreeWater | FP64 + GPU QP | 通过 |
| Simple2T-FreeWater | FP64 + GPU QP | 未通过，最大位置差 0.153496 mm |
| Full2T-FreeWater | FP64 + GPU QP | 未通过，CPU 47 点、GPU 45 点 |
| NODDI1F、NODDI2F | FP64 + GPU QP、Watson/Legendre 函数 | 小用例通过；真实数据限制见下文 |

FreeWater3T、NODDI3F 是原版未实现的模型，不属于这 12 种。NODDI 不支持张量分支或 Full Tensor 参数组合，CLI 明确拒绝这些组合。

`--gpuPrecision 1` 对 Simple1T/2T/3T 使用 FP32 插值/信号计算和 FP64 滤波；对 Full Tensor、FreeWater、NODDI 保留 FP64。不要把这些模型的 precision=1 结果描述为纯 FP32 加速。

## 具体修改

- `ukf/gpu/gpu_general.cuh`：Euler 张量、三张量、FreeWater 和 NODDI 信号预测、方向选择、状态/协方差交换、终止条件与记录。
- `ukf/gpu/gpu_qp.cuh`：固定维度 Goldfarb–Idnani 约束求解，保留原实现的 LGPL 署名。约束使用独立 CUDA 内核，避免 QP 局部数组使 Simple1T/2T 内核寄存器溢出。
- `ukf/gpu/gpu_noddi.cuh`：FP64 Watson、Dawson 等函数。与状态无关的协议和 Legendre 积分由主机预计算一次并上传。
- GPU 主机接口从实际模型提取状态维数、Q、D、d；支持分支事件下载、确定性排序和第二轮 GPU 追踪。初始化、后处理和 VTK 写出仍在 CPU。
- 共用原版修复：Full1T-FreeWater 工厂实例化错误；Watson SH 系数未初始化读取；QP 等式占位列错误参与活跃集索引；QP 删除约束时硬编码矩阵列错误。
- 分支修复：合法角度的余弦比较方向；附着位置由追踪步数改为实际记录点索引；分支种子标量初始化。CPU/GPU 同步修复，因而这些模型的 CPU 对照包含上述明确列出的修复，并非未经修改的上游二进制。
- 原 XML/CMake 配置文件本轮未覆盖。新配置为 `UKFTractography/UKFTractography-2026-10-10.xml`，包含 3T CLI 枚举；原 XML 的工作区改动来自此前阶段。

## 验证证据

日志目录：`/data/yijie/ukf-GPU/validation/all-models-2026-10-10/`。

1. `model-test-final.log`：12 种模型、每模型连续 20 步，GPU/CPU 最大状态误差约 6.59e-12、协方差误差约 9.37e-14；信号预测误差不超过 3.33e-16。包含 13 个 kappa 边界点的 Watson 检查。
2. `qp-test-final.log`：n=6/7/11/13 共 512 个约束测试，与修复后的 CPU 求解结果一致，并检查可行性和 KKT。
3. `model-memcheck.log`、`model-racecheck.log`、`model-synccheck.log`：零 CUDA 内存错误、零共享内存竞争警告、零同步错误。`qp-memcheck.log`：零错误、零显存泄漏。
4. `l1.log`：原 Simple1T/2T、FP64/混合 FP32、尾批及 800 步记录回归全部通过；memcheck/leak-check、racecheck、synccheck 全部通过。
5. `official-specialized.log`：12 个完整追踪用例中 6 个通过严格几何与全部标量检查，6 个仍失败，详见模型表。`official-fp64-scan.log` 是在其他用户占用显存时发生 OOM 的无效运行，不用于精度结论。
6. `branch-delivery.log`（保留失败）及 `branch-test-fast/branches-gpu.log`：GPU 生成 50 个分支种子并执行第二轮 GPU 追踪，CPU/GPU 最终均为 38 条纤维，但 1 条点数不同、19 条逐点误差超过 0.001 mm，因此严格分支检查仍失败。最终记录归一化修正后的 `branches-delivery-memcheck.log` 确认零 CUDA 内存错误、零显存泄漏。
7. 原全脑 2T 混合精度回归：288774 个种子纤维，总耗时 41.90 s，追踪 23.9556 s，VTK 写出 2.75053 s。与此前 `pages-final.vtk` 的几何、连接及全部记录数组完全一致。输出和日志保存在 `validation/speed-2026-10-10/all-models-regression.*`。共享机器上的 43.53→41.90 s 波动不单独归因为本轮加速。

## 真实 DWI 性能与精度

固定 RNG=20261010，从真实脑掩膜内部选 4096 个种子体素；每体素 1 个种子、最长半纤维 80 mm、无分支。CPU 16 线程；单张 RTX 4090；GPU FP64。包含 NMSE 及各模型标量记录。基准日志、固定种子文件、VTK、timings.json 和逐模型 comparison.log 在 `benchmark-large/`。

| 模型 | CPU 追踪 s | GPU 追踪 s | 追踪加速 | 总耗时加速 | wDice | 点数一致纤维 |
|---|---:|---:|---:|---:|---:|---:|
| Simple3T | 3.329 | 0.934 | 3.56× | 1.29× | 1.000000 | 1556/1556 |
| Full3T | 6.277 | 1.758 | 3.57× | 1.48× | 0.967305 | 1664/1782 |
| NODDI1F | 7.635 | 1.985 | 3.85× | 1.37× | 1.000000 | 1321/1321 |
| NODDI2F | 32.582 | 6.572 | 4.96× | 2.35× | 0.998363 | 1620/1638 |

Simple3T、NODDI1F 此真实数据子集的最大逐点误差为 3.815e-6 mm。Full3T、NODDI2F 存在长轨迹分歧；不能以高 wDice 代替严格一致性通过，也不能把基准加速比等同于精度验收。

512 种子的小批量中部分 GPU 模型更慢，数据加载约 7 s 主导总耗时。Full2T 追踪约 1.60×；Full2T-FreeWater 的 CPU 基准在约束求解异常后中止，未计算加速比。不要引用缺少有效 CPU 对照的速度数字。

底层模型/QP 测试可用 `NVCC=/data/yijie/miniconda3/envs/ukf-gpu/bin/nvcc bash tests/validate_model_kernels.sh /tmp/ukf-kernels` 复现；设置 `SANITIZE=1` 并把 compute-sanitizer 加入 PATH 可运行消毒器。完整分支严格比较可用 `tests/validate_branches.py --output <目录>`，当前预期保留失败。

## 构建和运行

```bash
cd /data/yijie/ukf-GPU/ukftractography
export LD_LIBRARY_PATH=/data/yijie/miniconda3/envs/ukf-gpu/lib:$LD_LIBRARY_PATH
CMAKE=/data/yijie/miniconda3/bin/cmake bash scripts/build_gpu_all_models.sh
# 使用日期版 XML 同时生成 ukf/ 与 UKFTractography/ 下的 CLP 头文件。
# 仅普通 cmake 构建会使用原 XML，干净构建时不具备 3T CLI 枚举。
CUDA_VISIBLE_DEVICES=4 /data/yijie/miniconda3/envs/tractography/bin/python \
  tests/validate_models.py --output /tmp/ukf-model-validation
# 严格验证仍会在已知失败模型处返回非零。
```

部署二进制：`/data/yijie/ukf-GPU/bin/UKFTractography_gpu`，配套共享库为 `build-gpu/lib/libukf_gpu.so`。本轮改变了 GPU 内部 ABI，必须使用配套二进制和库，不能混用旧可执行文件与新库。交付哈希见验证目录的 `delivery-sha256.txt`。旧二进制/源码备份在 `before/`，旧二进制不能直接与新共享库配对运行。
