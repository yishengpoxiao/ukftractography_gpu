# FP32 修复与验证（2026-10-10）

原版参考：https://github.com/pnlbwh/ukftractography ，本地 HEAD 为 `2d2b661`。
本次以现有未提交 GPU 移植为基础，未修改 CPU UKF 数学实现或现有配置文件。

## 现在的精度模式

- `--gpuPrecision 0`：FP64。
- `--gpuPrecision 1`：混合精度。DWI 高斯插值和 sigma 点信号预测用 FP32；位置、状态、协方差、sigma 点生成、UKF 信息形式更新、停止判断和记录保留 FP64。
- 默认仍为模式 0。模式 1 不保证真实全脑与 CPU 逐纤维一致，也不保证统计指标在任意数据/参数下等价。
- CLI XML 的旧说明仍写着 float 和逐位一致，属于前序遗留说明；以本文件和运行时 `precision=mixed-fp32` 日志为准。现有 XML/CMake 文件按配置保留规则未改动。

纯 FP32 对照实验中，官方 2T 的记录点数由 CPU 的 54 变为 59，最大位置差约 6.618 mm；保留 FP64 滤波核心后，点数恢复为 54，位置差降到 1.526e-5 mm。该实验支持保留敏感计算的 FP64 精度；它不是任意参数下的误差保证。

## 修复内容

1. 恢复缺失的 CUDA 可用性查询和波次循环，消除不存在的 `DeviceGuard`、`DevBufsF`、`kf_record_start` 等引用。接手时磁盘源码与交付文档不一致，无法直接构建。
2. 每次调用只分配一组分批缓冲，跨批复用；所有返回路径由资源对象释放显存。原代码在循环外、循环内重复分配且没有正确回收。
3. 最后一批只下载 `F * max_rec` 行；原代码按容量 `CF * max_rec` 下载，`F < CF` 时会越过主机输出数组。
4. 正确回填每批记录计数；全部波次内核按同一个活动纤维索引取数据，避免压缩后追踪错误纤维。
5. 显存预算使用上传常量后的实际空闲显存，不再用总显存替换空闲显存；拒绝零/负分批大小，避免零步长循环。
6. 显式按 FP32 算术计算信号，不再把 double 数组按 float 字节数截断拷贝。当前状态与表缓冲均为 FP64，进入信号计算时按数值转换。
7. 对非有限状态/协方差、失败的 Cholesky 对角线报告 GPU 路径失败，沿用已有 CPU 回退；不把数值失败当成正常提前终止。
8. 多卡工作线程状态改用独立整数元素，消除 `vector<bool>` 位打包写入竞争。
9. L1 参考补齐离开脑掩膜时的停止条件，并加入有限值、输出末尾哨兵、800 步和最终不足一批的回归覆盖。

## 已完成验证

产物目录：`/data/yijie/ukf-GPU/validation/fp32-2026-10-10/`。

- 最终 GPU CLI 增量构建通过：`build.log`。
- L1 1T/2T × FP64/混合精度 × 40/800 步全部通过：`l1-final.log`。每次三条种子、每批容量二，覆盖尾批。800 步测试使用 `L1_STEP=0.001` 和 `L1_SPR=1`，确保在体积内持续追踪。
- 800 步混合精度最大状态绝对误差：1T `1.708e-5`，2T `1.342e-5`；位置误差分别 `2.388e-7` / `2.589e-7`（体素坐标）；协方差误差 `2.862e-8` / `2.094e-8`。
- CUDA memcheck、racecheck、synccheck 均为 0 错误，racecheck 为 0 warnings；成功和错误返回路径的 leak check 均为 0 bytes。
- 官方 1T/2T，CPU/FP64/混合精度均成功。FP64 坐标与 CPU 完全相同；混合精度位置最大差分别 `7.629e-6` / `1.526e-5` mm，点数一致，wDice=1。包含 NMSE、FA、trace、covariance 记录，标量差异见 `official-comparison-final.log`。
- 对比工具的 PASS 只约束纤维条数、点数和位置容差；标量误差单独报告，不将 PASS 解读为所有标量逐位一致。
- CUDA sanitizer 覆盖的是有尾批、协方差记录的合成小任务，不是全脑 sanitizer 运行。

## 真实全脑（最终二进制，同参数顺序运行）

输入 `dwi.nhdr` / `dwi-mask.nhdr`；2T，288,774 个半纤维种子，输出均为 134,450 条纤维。参数见下面复现命令。GPU 固定设备 0；GPU 运行主机线程参数为 16，CPU 为 112。

| 模式 | 总墙钟 | 追踪阶段 |
|---|---:|---:|
| CPU 112 线程 | 94.86 s | 68.9267 s |
| GPU FP64 | 103.64 s | 79.1730 s |
| GPU 混合 FP32 | 69.34 s | 43.0266 s |

单次端到端测量：混合精度相对当前 FP64 为 1.495×，相对 CPU 112 线程为 1.368×。这台机器为多用户共享环境，不能把单次测量当成稳定性能保证。前序交付文档中的 64–68 秒 FP64 来自其他二进制，不能与本次直接混算加速比。

最终两种 GPU 模式均未触发 CPU 回退或数值失败。混合精度与 CPU 的 wDice 为 0.988054、占用 Dice 为 0.994813；FP64 与 CPU 的 wDice 为 0.999999、占用 Dice 为 1.000000。详见 `full-cpu-vs-mixed.log` / `full-cpu-vs-fp64.log`。FP64 与混合精度的 wDice 为 0.988054、占用 Dice 为 0.994813，但按输出顺序逐纤维点数及坐标对比未通过；高覆盖重叠不能代替逐纤维验收。

本次最终 FP64 与 CPU 的 134,450 条纤维记录点数全部一致；28 条纤维的位置误差超过 0.001 mm，最大 0.2634 mm、逐纤维最大误差的均值 5.908e-6 mm。该测量比前序文档描述更接近 CPU，但仍不能宣称全脑逐位一致。

## 复现命令

```bash
cd /data/yijie/ukf-GPU/ukftractography
export PATH=/data/yijie/miniconda3/envs/ukf-gpu/bin:$PATH
export LD_LIBRARY_PATH=/data/yijie/miniconda3/envs/ukf-gpu/lib:$LD_LIBRARY_PATH
SANITIZE=1 CUDA_VISIBLE_DEVICES=1 bash tests/validate_fp32.sh /tmp/ukf-fp32-validation

/data/yijie/miniconda3/bin/cmake --build ../build-gpu -j 8 --target UKFTractography
../bin/UKFTractography_gpu \
  --dwiFile UKFTractography/Data/Input/dwi.nhdr \
  --maskFile UKFTractography/Data/Input/dwi-mask.nhdr \
  --seedsPerVoxel 1 --numTensor 2 --numThreads 16 \
  --stoppingFA 0.10 --stoppingThreshold 0.05 --Qm 0.001 --Ql 10 --Rs 0.015 \
  --minBranchingAngle 0 --maxBranchingAngle 0 \
  --useGPU --gpuDevice 0 --gpuPrecision 1 --tracts /tmp/full2T_mixed.vtk
```

注意现有构建系统将 CLI 链接到 `../build-cpu/UKFTractography`，共享库在 `../build-gpu/lib/libukf_gpu.so`。二进制与共享库需配套；单独拷贝 CLI 不能作为可移植独立交付。
