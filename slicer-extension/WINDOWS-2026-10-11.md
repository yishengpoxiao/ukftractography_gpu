# Windows 11 / Slicer 5.6.2：构建与验收

## 当前状态

已实现 Windows 原生构建入口、DLL 导出、64 位 GPU 索引、Slicer 进程环境隔离、PE x64 检查、MSVC/CUDA 运行库打包，以及 CPU/GPU 严格精度验收脚本。**当前没有已编译、已验证的 Windows `.exe/.dll` 安装包**：本机是 Linux，没有 Windows/MSVC 编译器和 Windows NVIDIA GPU 可执行环境。本次交付的是 Windows 源码构建包，不能把它当成可直接运行的 Windows GPU 插件。

目标是 Windows 11 x64 + Slicer 5.6.2，安装目录使用 `Slicer-5.6`；其他 Slicer 5.x 可通过参数选择对应主次版本。实际完成的是 Linux 上的 Slicer 5.6.2/5.12.4 验证，尚不能据此宣称 Windows 或任意 Slicer 版本实测通过。

## 准备环境

在可用于构建的 Windows 电脑安装：

- Visual Studio 2022 / Build Tools：Desktop development with C++、MSVC x64 工具、Windows SDK。
- CUDA Toolkit ≥12.1：选择与 MSVC 编译器、显卡架构兼容的 Toolkit 版本。较新显卡应选择支持其架构的 Toolkit。编译器支持范围查阅 [NVIDIA Windows 安装指南](https://docs.nvidia.com/cuda/cuda-installation-guide-microsoft-windows/index.html)。
- CMake ≥3.22、Ninja、Git、Python 3.9+，均加入 PATH。
- 用于运行验收的 NVIDIA GPU、驱动和 Slicer 5.6.2。

`CUDA UMD Version: 13.4` 是驱动侧信息，不等于安装了 Toolkit 13.4。编译前检查 `nvcc --version`；运行条件检查 `nvidia-smi`。用户只安装最终运行包时不需要 Visual Studio、CMake 或 Toolkit，但需要兼容的 NVIDIA 驱动。

解压源码包到较短的目录，例如 `C:\UKF\src`，避免依赖源码构建遇到 Windows 长路径问题。打开 **x64 Developer PowerShell for VS 2022**，确认 `cl.exe`、`nvcc.exe`、`cmake.exe`、`ninja.exe`、`git.exe` 可用。脚本不修改全局 Git、CUDA、Visual Studio 或 Slicer 配置。

## 构建并生成 Windows 安装包

在源码根目录运行：

```powershell
.\scripts\build_windows_gpu.ps1 `
  -BuildDirectory C:\UKF\build `
  -PackageDirectory C:\UKF\package-5.6 `
  -SlicerVersion 5.6 `
  -CudaPath 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8'
```

`-CudaPath` 应替换为实际安装位置。`PackageDirectory` 必须不存在；脚本不会覆盖已有包。

脚本使用新入口 `platforms/superbuild-2026-10-11`，从固定版本源码构建 ITK、VTK、Teem、Eigen、SlicerExecutionModel、zlib，然后编译 GPU 后端；首次需要联网且依赖构建可能较久。不需要编译 Slicer，也不依赖本机 Slicer SDK。原有 CMake/XML 文件保持不变。

默认从 `nvcc --list-gpu-code` 查询编译器能力，在 75/80/86/89/90/100/120 中选择支持的常用架构，并保留最低所选架构的 PTX。这样可覆盖多代显卡，而非只生成 RTX 4090 的 sm_89 代码。不同显卡仍需要实测；PTX 前向兼容不等于所有未来硬件都经过验证。可显式指定，例如只构建 RTX 4090：

```powershell
.\scripts\build_windows_gpu.ps1 `
  -BuildDirectory C:\UKF\build-4090 `
  -PackageDirectory C:\UKF\package-4090 `
  -SlicerVersion 5.6 `
  -CudaArchitectures '89-real;89-virtual'
```

MSVC runtime 默认取 `$env:VCToolsRedistDir\x64\Microsoft.VC143.CRT`；如不在该位置，用 `-MsvcRuntimeDirectory` 指定实际的 x64 CRT 目录。包内包括 `.exe`、`ukf_gpu.dll`、`cudart64_*.dll` 和 CRT DLL。脚本检查 GPU DLL 导出，并在排除开发环境 PATH 后执行包内程序 `--help`，尽早发现缺失 DLL。

Windows 直接用 QProcess 启动 `.exe`，不依赖 `.sh`、`.bat` 或 WSL。程序使用 UTF-8 manifest；含空格/中文路径的 argv 构造已测试，Windows 后端实际中文路径 I/O 仍需实机验证。

## Windows 精度验收

先对两个已有基础模型进行验收：

```powershell
python .\scripts\validate_windows_gpu.py `
  --slicer 'C:\Program Files\Slicer 5.6.2\Slicer.exe' `
  --binary 'C:\UKF\package-5.6\UKFGPU\UKFGPU\Runtime\bin\UKFTractography_gpu.exe' `
  --output C:\UKF\validation-basic `
  --models simple1 simple2
```

然后使用新的输出目录、不指定 `--models`，检查全部 12 模型。验证器通过 Slicer 自带的 VTK/Numpy 读取结果，不要求系统 Python 安装它们。输出 CPU、FP64 GPU、混合 GPU 的 VTK、日志和 `acceptance.json`。返回非零或 JSON 中 `passed: false` 表示未通过；不得改成“支持全部模型已验收”。

完整验收仍要求按顺序逐纤维点数一致、位置欧氏距离 ≤0.001 mm，并检查记录数组的既有容差。所有模型都要求日志确认真实 GPU 执行，CPU 回退不能算成功。当前算法在部分模型上已有严格精度失败，Windows 移植不豁免这些失败。

## Slicer 安装

构建、DLL 加载和 GPU 验收通过后，在 Slicer **Extensions Manager → Install from file** 选择生成的 `UKFGPU-Slicer5.6-windows-x86_64-YYYY-MM-DD.tar.gz`，重启 Slicer。模块位置：**Diffusion → Tractography → UKF GPU Tractography**。

升级到 Slicer 5.12 时重新打包 `-SlicerVersion 5.12`，不要把 `5.6` 安装目录的包直接当作 `5.12` 包。已有 Windows 后端也可独立打包：

```powershell
python .\scripts\package_slicer_extension.py `
  --platform windows `
  --binary C:\UKF\build\backend\bin\UKFTractography_gpu.exe `
  --gpu-library C:\UKF\build\backend\bin\ukf_gpu.dll `
  --cuda-runtime 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8\bin\cudart64_12.dll' `
  --runtime-dir 'C:\path\to\x64\Microsoft.VC143.CRT' `
  --slicer-version 5.6 `
  --output C:\UKF\new-package
```

打包器拒绝 Linux 文件和非 x64 PE 文件，不能用 Linux 二进制改名生成 Windows 包。GPU 可执行文件和 DLL 必须来自同一次完整构建，不能混用早期 ABI 的产物。
