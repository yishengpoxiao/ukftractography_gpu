# UKF GPU: 3D Slicer Extension

This extension connects the CUDA UKF backend to Slicer. It provides 12 experimental models, FP64/mixed precision, GPU selection, tracking and recording options, asynchronous execution, cancellation, logs, and fiber display.

Linux integration has been tested with Slicer 5.2.2, 5.6.2 and 5.12.4. The scene-first workflow and hover help were validated with Slicer 5.2.2; see the [current validation report](VALIDATION-2026-10-12.md). Windows native build and packaging support targets Windows 11 / Slicer 5.6.2; **no Windows binary has been compiled and validated yet**. See the [Windows guide](WINDOWS-2026-10-11.md).

## Install

For an installation archive generated by the packager:

1. Open **Extensions Manager**, then **Install from file...**.
2. Select `UKFGPU-Slicer<major.minor>-<platform>-x86_64-<date>.tar.gz` matching your Slicer version and platform.
3. Restart Slicer and open **Diffusion > Tractography > UKF GPU Tractography**.

Archives and compiled runtimes are not included in this repository. The extension is not published in the online Extensions Catalog.

To load the script from source, add `slicer-extension/UKFGPU` to **Edit > Application Settings > Modules > Additional module paths**, then restart Slicer. Select a compiled backend in the module or set `UKF_GPU_EXECUTABLE`. For packaged Linux runtimes, use `Runtime/bin/ukf-gpu`; for Windows, use `Runtime/bin/UKFTractography_gpu.exe`.

The tested Linux runtime targets RTX 4090 / sm_89 and requires a CUDA 12.1-compatible NVIDIA driver, glibc 2.29+, and GLIBCXX_3.4.26. Rebuild for other GPU architectures. There is no macOS CUDA backend.

## Use

1. Load a DWI NRRD with DWMRI gradients and b-value metadata.
2. Select the brain mask and optional seed labelmap. Export segmentation nodes to labelmaps first; enter labels separated by commas.
3. Select the model and precision. The GPU list automatically shows backend-visible CUDA ordinals, names and total memory. Click **Refresh** after changing the backend. Detection runs in a separate process and respects `CUDA_VISIBLE_DEVICES`; if discovery fails, a manual CUDA index is available. When discovery confirms no visible device, tracking is disabled until a successful refresh.
4. Set **Fiber name** if desired; leave it empty to use `UKF_<model>`. Duplicate names are automatically distinguished by Slicer. Choose a **Tracking preset** and click **Apply**, or adjust **Tracking and recording**, then click **Run GPU tracking**. No output path is required.
5. Fibers are added directly to the current scene and displayed on completion. Use Slicer's **Save** dialog to save the fibers or scene when needed. Temporary tracking inputs and output are removed after import; unsaved fibers are lost when the scene is discarded. Cancellation or failure also removes the job's temporary files. Logs remain in the module's log panel for inspection and copying.

Hover over parameter labels or controls to see their purpose, units, defaults, model applicability, and relevant runtime/memory implications. Recording checkboxes also explain the arrays they add.

Available presets are **Standard**, **Quick preview**, and **Fine sampling**. Standard uses model-specific filter noise defaults and standard sampling (0.3/0.9 mm step/record spacing for 1T/2T, 0.15/0.45 mm for 3T). Quick preview limits each half-fiber to 50 mm and uses 1.8 mm recording spacing. Fine sampling halves the standard step and record spacing; it costs more computation and does not guarantee better anatomical accuracy. Apply replaces tracking parameters and clears all recording options, while preserving model, precision, device, inputs and fiber name. Selecting a preset alone does not overwrite manual settings.

Controls are enabled by model: tensor FA/eigenvalue parameters and tensor recording, FreeWater noise/recording, and NODDI noise/recording. Branching additionally requires a multi-tensor model and a seed labelmap. Switching models clears incompatible record flags and disables unsupported precision selection; Full Tensor, FreeWater and NODDI use FP64. Disabled numeric options are omitted from the backend command.

Models include Simple1T/2T/3T, Full1T/2T/3T, Simple1T/2T-FreeWater, Full1T/2T-FreeWater, and NODDI1F/2F. Mixed precision lowers selected Simple-model signal calculations to FP32; sensitive calculations and other models retain FP64. Zero Qm/Ql/Qw/Rs values use backend model defaults. Branching is disabled by default.

With SlicerDMRI's FiberBundle node class available, fibers are imported as a FiberBundle; otherwise, a Model node is used. Automated integration currently covers the Model path; SlicerDMRI-specific display remains unverified. UKF VTK coordinates are RAS and are read directly to avoid a generic reader's LPS conversion. Input export preserves original node storage paths. Inputs with parent transforms are unsupported; use aligned volumes without parent transforms.

Unavailable GPUs or a backend CPU fallback are reported as failures. Inspect the retained log for driver, runtime, parameter, or algorithm errors.

## Accuracy

The interface does not resolve existing CPU/GPU algorithm differences. Some full-tensor, two-tensor FreeWater, long NODDI2F, degenerate Simple3T, branching, and whole-brain cases fail strict acceptance. The requirement is identical fiber order and per-fiber point counts, with positional Euclidean error at most 0.001 mm. A successful GPU run or regression against previous GPU output does not establish CPU agreement. See the [accuracy report](../tests/严格精度验收-2026-10-11.md).

## Package

From the repository root, use a new output directory:

```bash
python scripts/package_slicer_extension.py \
  --binary /path/to/UKFTractography_gpu \
  --gpu-library /path/to/libukf_gpu.so \
  --cuda-runtime /path/to/libcudart.so.12 \
  --slicer-version 5.12 \
  --output /new/package-directory
```

The Linux packager copies and strips binaries, removes development RPATHs, and creates a launcher using packaged GPU/CUDA libraries. If the CUDA runtime directory contains a LICENSE file, it is included. Outputs include a source/runtime archive and a version-specific Extensions Manager archive. Repackage and validate when changing Slicer versions. Windows packaging commands are in the [Windows guide](WINDOWS-2026-10-11.md).

An SDK build entry is also provided:

```bash
cmake -S slicer-extension -B /new/UKFGPU-build -DSlicer_DIR=/path/to/Slicer-build
cmake --build /new/UKFGPU-build --target package
```

The SDK/CMake route remains unverified. Source does not contain a Runtime directory; supply a backend explicitly or build from a packaged source/runtime tree.

## Integration tests

```bash
UKF_TEST_REPOSITORY=/path/to/ukftractography_gpu \
UKF_TEST_OUTPUT=/new/test-output \
UKF_GPU_EXECUTABLE=/path/to/Runtime/bin/ukf-gpu \
CUDA_VISIBLE_DEVICES=0 xvfb-run -a /path/to/Slicer \
  --no-splash --no-main-window \
  --additional-module-paths /path/to/UKFGPU-module-directory \
  --python-script slicer-extension/UKFGPU/Testing/slicer_integration.py
```

This historical regression test requires GPU reference outputs from `validation/reference-gpu`, which are not included in the repository. It checks widgets, three models' export/run/import flow, geometry, recorded arrays, cancellation, and failure cleanup. It is not full CPU accuracy acceptance. See the [integration report](VALIDATION-2026-10-11.md).
