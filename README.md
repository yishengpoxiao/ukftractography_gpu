# UKFTractography GPU

CUDA acceleration for unscented Kalman filter diffusion MRI tractography, with a command-line backend and a 3D Slicer extension.

This is a modified version of [pnlbwh/ukftractography](https://github.com/pnlbwh/ukftractography), based on upstream commit `2d2b661`. The original authors' contributions, source notices, and [license](LICENSE.txt) are retained.

## Features and current status

- GPU filtering, constraints, tracking, and recording for 12 experimental models: Simple1T/2T/3T, Full1T/2T/3T, Simple1T/2T-FreeWater, Full1T/2T-FreeWater, and NODDI1F/2F.
- FP64 by default, with optional mixed precision. `--gpuPrecision 1` uses FP32 for Simple1T/2T signal calculations while sensitive calculations remain FP64; other models retain FP64. Mixed precision can exceed the strict position tolerance on real data; use `--gpuPrecision 0` for strict CPU comparison.
- Tracking kernel and record-transfer optimizations, including batched active-list compaction, parallel NODDI sigma observations, cached FreeWater observations, reused polynomial recurrences, and compact downloads.
- A Slicer interface with input validation, automatic GPU discovery/free-memory recommendation, single or explicitly selected multi-GPU tracking, real completion counts and elapsed time, scene-persistent parameters, custom fiber names, and direction/FA/length/solid coloring.
- Linux integration tested with Slicer 5.2.2, 5.6.2 and 5.12.4. Tracking results appear directly in the scene; parameter controls provide hover help. Windows native compilation, CPU execution, and extension installation have been checked in CI with Slicer 5.6.2 and 5.12.4. Windows GPU tracking still requires verification on NVIDIA hardware.

Accuracy acceptance requires the same fiber order and per-fiber point counts, positional Euclidean error at most **0.001 mm**, and recorded-array checks. Results remain workload-specific; long whole-brain, branching, and other platform/device combinations require separate validation. Full2T FreeWater can also fail in the upstream CPU constraint solver for some inputs; the original CPU baseline is retained, and these inputs remain a known limitation. The upstream zero-tensor FreeWater case can produce NaN FA; its CPU behavior is intentionally preserved, and that case does not pass finite-record validation.

## Build

Clone this repository:

```bash
git clone https://github.com/yishengpoxiao/ukftractography_gpu.git
cd ukftractography_gpu
```

The standalone backend requires a C++17 compiler, CMake 3.22+, CUDA Toolkit compatible with your compiler and GPU, ITK 5, VTK 9, Eigen 3.4, Teem, SlicerExecutionModel, and zlib. Use a CUDA Toolkit that supports your compiler and GPU architecture.

With dependencies already available, configure `platforms/standalone-2026-10-14-r2` and provide their CMake package paths. Alternatively, the dependency superbuild provides pinned dependency sources:

```bash
cmake -S platforms/superbuild-2026-10-14-r4 -B ../build-ukfgpu \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/path/to/nvcc
cmake --build ../build-ukfgpu --parallel 8
```

GPU targets are detected from `nvcc --list-gpu-code`; no fixed CUDA Toolkit version is required. Override with `-DUKF_CUDA_ARCHITECTURES="75-real;89-real;75-virtual"` when needed. The Toolkit must support C++17 and the selected host compiler. The backend is produced in `../build-ukfgpu/backend/bin/`. The standalone backend has been compiled and checked on Linux; a complete dependency superbuild from scratch remains to be verified.

On Windows, run from **x64 Developer PowerShell for VS 2022**:

```powershell
.\scripts\build_windows_gpu.ps1 `
  -BuildDirectory C:\UKF\build `
  -PackageDirectory C:\UKF\package-5.6 `
  -SlicerVersion 5.6 `
  -CudaPath 'C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8'
```

Adjust `CudaPath` to your installed Toolkit. See the [Windows build guide](slicer-extension/WINDOWS.md) for prerequisites, architecture selection, and runtime libraries. Native Windows installers are generated by the Windows installer workflow; GPU execution still needs hardware validation.

## Command-line usage

```bash
/path/to/UKFTractography_gpu \
  --dwiFile UKFTractography/Data/Input/two_tensor.nhdr \
  --maskFile UKFTractography/Data/Input/mask.nhdr \
  --seedsFile UKFTractography/Data/Input/seed.nhdr \
  --tracts /new/output/fibers.vtk \
  --numTensor 2 --seedsPerVoxel 1 --useGPU \
  --gpuDevice 0 --gpuPrecision 0
```

Run the executable with `--help` for the complete option list. The output directory must exist. Runtime library search paths must include the GPU library and CUDA runtime; packaged Slicer runtimes handle this through their launcher.

## 3D Slicer

Download installers, installation instructions and SHA-256 checksums from the [2026-10-15 preview release](https://github.com/yishengpoxiao/ukftractography_gpu/releases/tag/v0.3.0-preview.20261015). The version-adaptive installer ZIP contains native Linux and Windows backends. Separate Slicer installation archives are also available.

The [offline installer](slicer-extension/INSTALLER.md) adapts its installation layout to the running Slicer 5.2 or newer version and installs bundled native dependencies privately. The bundle includes Linux x86_64 and Windows x86_64 runtimes. NVIDIA graphics drivers are a system prerequisite.

See the [extension README](slicer-extension/README.md) for installation, packaging, and usage. The extension is not currently published in the online Extensions Catalog. Source checkout alone does not include a compiled backend.

## Development and data

Small synthetic inputs and CPU baselines are included. The approximately 100 MB upstream whole-brain DWI payload is excluded from the source tree. Restore it when needed:

```bash
python scripts/fetch_benchmark_data.py
```

This downloads the data from a pinned upstream commit and checks its SHA-256 hash. The matching header and masks remain in `UKFTractography/Data/Input/`.

Current standalone build entries are listed in [platforms/README.md](platforms/README.md). The Windows installer workflow checks native compilation, CPU execution, packaging contracts, and actual extension installation/module loading. Python unit and installation checks are in `slicer-extension/UKFGPU/Testing/`.

Numerical acceptance scripts, benchmark reports, generated results, build outputs, and packaged runtimes are maintained outside this repository. Original upstream CPU regression tests and their input/baseline data are retained for the upstream build route.
